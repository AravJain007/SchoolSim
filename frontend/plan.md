This document details the architecture, components, and integration points for the frontend of the LLM Classroom Simulation project. The implementation will use the **Phaser 3** game framework to create a dynamic, retro-style visual experience.

-----

## 1\. Project Overview  Classroom Simulation 🍎

The frontend will render a 2D, pixel-art classroom environment. It will receive commands from an external backend (via a JavaScript event bus) to display dialogue in speech bubbles above specific characters. The simulation will follow a lecture format where a teacher character delivers content, student characters can interject with questions, and the teacher provides answers. The entire application is divided into two states: an initial **Setup Screen** (HTML/CSS) for configuration and the main **Simulation Scene** (Phaser/Canvas) for the visual display.

-----

## 2\. Core Technologies

  * **Game Framework**: **Phaser 3** (v3.60.0 or later).
  * **Language**: **JavaScript (ES6)**. All simulation logic will be encapsulated within a `ClassroomScene` class extending `Phaser.Scene`.
  * **Rendering**: Phaser's `AUTO` setting, which prioritizes **WebGL** and falls back to **Canvas**. The `pixelArt: true` flag in the game configuration is mandatory to ensure a crisp, non-blurry aesthetic.
  * **UI Font**: **'Press Start 2P'** from Google Fonts for all in-game text to maintain the retro theme.
  * **Asset Generation**: All visual assets (sprites, tiles, UI elements) will be **procedurally generated** at runtime using Phaser's dynamic texture creation capabilities. No external image files will be loaded.

-----

## 3\. Application States & UI Flow

The application flow is a simple two-step process managed by a standard HTML page and a main JavaScript file.

### State 1: Setup Screen (HTML/CSS)

This is the initial user-facing interface, built with standard HTML and styled with CSS.

**UI Components:**

  * **Main Container**: A `div` with a dark background (`#1a1a1a`), a solid light-gray border, and centered on the page.
  * **Title**: An `<h1>` element with the text "Classroom Setup".
  * **Teacher Name Input**: An `<input type="text">` for setting the teacher's name.
  * **Student Count Input**: An `<input type="number">` for selecting the number of students.
  * **Start Button**: A `<button>` with the text "Start Class".

**Functionality:**

1.  The user enters the teacher's name and the desired number of students.
2.  Clicking the "Start Class" button triggers a JavaScript function.
3.  This function hides the setup screen container (`display: none;`).
4.  It then instantiates the Phaser game, passing the teacher's name and selected student count as initialization data to the `ClassroomScene`.

### State 2: Simulation Scene (Phaser Canvas)

This is the core visual component, rendered by Phaser inside the `<div id="game-container">`.

**Canvas Configuration:**

  * **Dimensions**: 1000px width x 750px height.
  * **Parent**: The canvas is attached to the `#game-container` div.

**Scene Composition:**

  * **Background**: A tiled floor pattern is generated by creating a 4x4 pixel texture with a checkerboard pattern and setting it as a repeating `TileSprite`.
  * **Environment**: A large, dark green rectangle representing a chalkboard is placed at the top-center of the scene.
  * **Characters & Desks**:
      * One **Teacher** sprite ("Prof. Oak") is placed at the front, near the chalkboard.
      * `N` **Student** sprites and `N` **Desk** sprites are generated based on the number selected on the setup screen.
      * The layout is a grid. The number of columns is fixed (e.g., 10), and new rows are added as needed to accommodate all students.
      * **Sprite Variation**: Student sprites will alternate between at least two procedurally generated designs (e.g., different shirt colors) to break up visual monotony.

## 4\. Key Features & Required Functionality

### 4.1. Dynamic Character Generation & Placement

The `ClassroomScene`'s `create(data)` method will receive the configuration data (`{ teacherName, studentCount }`). A loop will then instantiate and position each student and their desk.

  * **Data Structure**: A `Map` or `Object` will be used to store character game objects, keyed by a unique name. The teacher's name will be taken from the setup data (e.g., `'Prof. Ada'`), and students will be systematically named (e.g., `'Student_15'`). This allows for quick lookups when an event is received.
  * **Positioning Logic**:
      * `const columns = 10;`
      * `const spacingX = 90;`
      * `const spacingY = 110;`
      * `const startX = 80;`
      * `const startY = 250;`
      * The position of each student `i` will be calculated as:
          * `x = startX + (i % columns) * spacingX;`
          * `y = startY + Math.floor(i / columns) * spacingY;`

### 4.2. Speech Bubble System 💬

This system is the primary interface for displaying LLM-generated text. It will be managed within the `ClassroomScene`.

**Visual Style:**
A `Phaser.GameObjects.Container` will be used to group the speech bubble components:

  * **Background**: A white rectangle with a 4px black border.
  * **Pointer**: A black triangle shape (`Phaser.GameObjects.Triangle`) positioned at the bottom-center of the background.
  * **Text**: A `Phaser.GameObjects.BitmapText` or `Text` object using the 'Press Start 2P' font, centered within the background.

**Core Functions (Internal to the Scene):**

  * `showSpeechBubble(character, text)`:
    1.  First, it checks if another speech bubble is active. If so, it calls `hideSpeechBubble` on the currently speaking character.
    2.  It brings the target `character` to the top of the display list by setting a high depth value (e.g., `character.setDepth(10)`). This ensures the character and their bubble render over other students.
    3.  It creates or re-uses a speech bubble container.
    4.  The `text` content is set, and the bubble's background may resize dynamically to fit.
    5.  The bubble is positioned above the character's head.
    6.  A **Phaser Tween** is used to fade the bubble in (from `alpha: 0` to `alpha: 1`) over 200ms for a smooth appearance.
  * `hideSpeechBubble(character)`:
    1.  Resets the character's depth to its original value (e.g., `character.setDepth(1)`).
    2.  Uses a **Phaser Tween** to fade the associated speech bubble out (from `alpha: 1` to `alpha: 0`) over 200ms.
    3.  On tween completion, the bubble container is set to `setVisible(false)`.

## 5\. External API for Backend Integration

The simulation exposes a clean event-based API. An external script (e.g., a vanilla JS module, React component, etc.) can control the simulation by emitting events on the global game instance.

**Setup:**
The main script that creates the Phaser game will attach the instance to the `window` object.
`window.game = new Phaser.Game(config);`

**Event Listeners (inside `ClassroomScene`'s `create` method):**

```javascript
// Listen for the command to show dialogue
this.game.events.on('display-dialogue', (characterName, text) => {
    const character = this.characters.get(characterName);
    if (character) {
        this.showSpeechBubble(character, text);
    }
});

// Listen for the command to hide dialogue
this.game.events.on('hide-dialogue', (characterName) => {
    const character = this.characters.get(characterName);
    if (character) {
        this.hideSpeechBubble(character);
    }
});
```

### Event: `display-dialogue`

  * **Purpose**: Instructs the simulation to display a speech bubble for a specific character. This is the primary event used for all dialogue, including the teacher's lecture, student questions, and teacher answers.
  * **Arguments**:
      * `characterName` (String): The unique identifier for the character (e.g., `'Prof. Ada'`, `'Student_5'`).
      * `text` (String): The dialogue to be displayed.
  * **Example Usage (from outside Phaser)**:
    ```javascript
    window.game.events.emit('display-dialogue', 'Student_5', 'What is an API?');
    ```

### Event: `hide-dialogue`

  * **Purpose**: Instructs the simulation to hide the speech bubble of a specific character.
  * **Arguments**:
      * `characterName` (String): The unique identifier of the character.
  * **Example Usage (from outside Phaser)**:
    ```javascript
    window.game.events.emit('hide-dialogue', 'Prof. Oak');
    ```

### Example Simulation Flow

The backend will drive the classroom simulation by emitting a sequence of events. The frontend simply listens and visualizes the dialogue.

1.  **Teacher Starts Lecture**: The backend sends an event to show the teacher's first line.
    ```javascript
    // Backend logic sends this after a 1-second delay
    window.game.events.emit('display-dialogue', 'Prof. Ada', 'Good morning, class. Today, we will discuss Object-Oriented Programming.');
    ```
2.  **Student Asks a Question**: Based on its internal logic, the backend determines a student has a doubt.
    ```javascript
    // Backend logic sends this after a 5-second delay
    window.game.events.emit('display-dialogue', 'Student_12', 'Professor, what is a "class" in this context?');
    ```
3.  **Teacher Responds**: The backend processes the question and provides an answer.
    ```javascript
    // Backend logic sends this after another 4-second delay
    window.game.events.emit('display-dialogue', 'Prof. Ada', 'Excellent question. A class is a blueprint for creating objects.');
    ```
4.  **Lecture Continues**: The process repeats until the backend concludes the lecture. The simulation ends when no more events are sent.
